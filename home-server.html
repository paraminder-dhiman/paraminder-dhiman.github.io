Home Server and Automation

Infrastructure · Unraid, Docker, Python · 2026

    A home server I designed, built and run for friends and family. It streams media, signs people up through a Discord bot I wrote, and backs itself up every week.

    I did all of it myself, from the hardware and the network to the containers and the code. It started as a way to learn how networking works, and it turned into a small service that people use every day.

    • 4 user tiers
    • 3 copies of every backup
    • 7 weeks of backups kept
    • 0 ports open to the internet

    How it fits together

    People come in through a Cloudflare Tunnel or through Discord. Admin access is over Tailscale only.

    What runs on it

    Hardware

    A Ryzen 9 build with an RTX 2070 Super, which handles video encoding in hardware. I moved the server onto it from a small office desktop.

    Platform

    Unraid, with every service in its own Docker container. App data sits on an NVMe cache and the library on a four-drive array.

    Media streaming

    Jellyfin with four user tiers. Each tier sets a bitrate cap, a session limit and whether group watching is allowed.

    Library preparation

    A Tdarr pipeline runs on the graphics card. It re-encodes the library and health-checks every file, so most devices play files directly and the server rarely has to transcode.

    Network

    AdGuard Home filters DNS and is also the network's DHCP server, so every lease lives in one place.

    Remote access

    Public services go out through Cloudflare Tunnels. Anything administrative is reachable over Tailscale only.

    Monitoring

    Uptime Kuma watches the services, and a speed test tracker logs the connection over time.

    Power

    My workstation stays off unless it's needed and is woken over the network when it is.

    The Discord bot

    Everyone who uses the server is in one Discord server, so I wrote a bot to run the front desk. It's Python with discord.py and slash commands. Each feature is its own module, loaded automatically at start, and the bot runs as its own container.

    Onboarding

    1. RequestA new member gets a guest role and a Request access button.
    2. ReviewThe request lands in an admin channel with Approve, Approve as trusted and Decline.
    3. AccountApproving creates the streaming account on the right tier and swaps the member's role.
    4. LoginThe login details arrive in a direct message. Declining sends the reason instead.

    Accounts

    Creates streaming accounts with the tier's limits applied, and keeps a map between Discord members and their accounts.

    Library

    Commands for library stats, search and what was added recently.

    Code

    Kept in a private Git repository. Secrets and data files stay out of version control.

    Housekeeping service

    A second, smaller Python service runs in its own container and looks after jobs between the server and my workstation. Files are handed over in three steps, so nothing is lost if one fails.

    1. CopyThe file is copied to the other machine.
    2. VerifyThe copy is checked against the original.
    3. DeleteOnly then is the original removed.

    Every action it takes is posted as one line to a private Discord channel through a webhook. It also raises a flag if no backup has run in eight days.

    Backups

    App data and the boot drive are backed up once a week, at a time when I'm home to fix whatever breaks. Seven backups are kept, which covers the last 50 days. I chose weekly over daily because only a few people use the server on any given day.

    1. Flash driveThe weekly backup is written here first.
    2. Second driveThen copied to another drive in the server.
    3. WorkstationAnd copied again to my workstation.

    Design decisions

    Nothing is open to the internet, and everything the server does is written down where I can read it.

    No open ports

    Nothing on the router is opened to the internet. Public pages go out through Cloudflare Tunnels, and admin access is over Tailscale only, so there's nothing to scan or attack from outside.

    One place for the network

    AdGuard Home is also the DHCP server, so every device's address and every DNS rule live in one place instead of being split with the router.

    Encode once, direct play everywhere

    The library is re-encoded once to a format almost every device plays directly. That costs a one-off pass on the graphics card, but means the server rarely transcodes while people watch.

    Separate services

    The Discord bot and the housekeeping service are separate programs, each in its own container and Git repository. Media-facing jobs go to the bot, and jobs between machines go to the housekeeping service, so one can change without risking the other.

    Logs you can read

    Every automated action is posted as a single line to a private channel, so I can see what happened without opening a terminal. Noisy events are left out on purpose.
